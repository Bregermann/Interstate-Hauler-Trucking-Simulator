# Schema 4 identity-preserving reader and application

This is an extension of the existing `DragonKingdomWorldAdoptionPlan` and Apply
path. It does not run adoption, regenerate the world or approve a candidate.
The saved-architecture validator remains the authority for the new source,
material, footing, retained-building and waterfront binding evidence.

Schema 4 planning requires the actual passed full native integration receipt,
its independent source-footing collider proof, and a reloaded persistent world
passing `ValidateSavedFinishedArchitecture`. Merely setting a schema number or
having the V327 source-stage receipt does not pass.

Exactly four complete architecture frames and one physically proven waterfront
support root are classified separately from the original 343 finish roots. The
existing schema 3 authored-group validator still verifies its original 335 source
instances and material provenance through a narrow schema 3 view. The original
receipt is not modified. Legacy schema 0/2/3 rules remain unchanged.

The ten original houses moved by the native base seater are matched using their
actual source correspondence GUID/local IDs, original name, exact source prefab
and measured final pose. New streetfront/refuge houses still require the original
finish-source provenance and their separately validated native final pose.

The old castle's 26 obsolete renderer/collider components are **disabled**, not
removed. Planning records each original/candidate ID, component type/path,
original source local ID, source JSON witness and enabled state. All original
transforms, components, four perch references and eight physical support-tower
components remain in the ordinary original-object map. The complete castle mesh,
collider shape/material, relative geometry and transform hierarchy must remain
unchanged apart from the exact declared enabled-state differences.

Apply copies a generic collider enabled state only for schema 4 and only if the
exact candidate component maps to its whitelisted original component, with the
candidate disabled. Renderer retirement uses the same whitelist; the existing
lake replacement exception remains independent. No arbitrary collider/renderer
disable, component deletion or reconstructed original identity is authorized.

After the canonical prefab has been saved, the original preview may already
inherit those exact disabled states. Its subsequent map permits that idempotent
state only under the same 26-ID proof. Initial planning still requires the exact
original source bytes and enabled states. The existing visual, mounted-course,
retention, source/GUID, rollback, mode, navigation and explicit-application gates
remain in force.

Three new targeted tests cover missing schema 4 evidence, an unwhitelisted
collider disable, and actual original-castle clone retirement/mapping with three
fault controls. The castle probe uses the existing Retire tool and the actual
strict native geometry receipt; it never writes the canonical asset. Its positive
result establishes only component-map closure, not full saved-world acceptance.

Use `-tsDragonArchitectureGeometry <actual strict geometry receipt>` for that
native component-map test. Exact files/compiler results are recorded in
`Logs/TruckSports/DragonKingdom/Schema4AdoptionReady01/status.json`.

Actual complete schema 4 saved-positive planning/application remains unverified
until the world candidate, terrain, waterfront, persistent materials and accepted
18 regional images exist. No canonical adoption is performed by these changes.
Any additional physical crossing/bridge roots require their own exact saved
identity contract; this architecture extension does not silently accept them.

VENDOR ASSETS AUDITED: existing native prefab/source-GUID correspondence APIs,
exact castle source and component boundary, existing identity adoption/rollback,
source architecture and public-upgraded material verification adapters.

VENDOR ASSETS USED: original complete source ensembles, original castle/perch
objects, public Unity prefab and serialization APIs and existing physical proofs.

RELEVANT ASSETS NOT USED: runtime Pixel Crushers save orchestration is unrelated
to this explicit Editor-only prefab identity migration.

CUSTOM SYSTEMS CREATED: narrow schema 4 receipt, component-state whitelist and
original-house correspondence extension of the existing adoption authority.

VENDOR SOURCE MODIFIED: none.

DUPLICATE VENDOR FUNCTIONALITY CREATED: none.
