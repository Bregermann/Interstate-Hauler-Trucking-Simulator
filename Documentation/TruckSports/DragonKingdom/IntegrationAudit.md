### Match, participant and score ownership

`Assets/TruckSports/Scripts/SportsEventSession.cs` provides the foundation for all **four** new games:

- Subclass entry points: `BeginGame()`, `Simulate(float dt)`, `Present(float dt)`, `StopGame()`, `SetPaused(bool)`, `StopSounds()`.
- `StartMatch()` validates device sources, saves setup, applies `SportsMatchColors`, prepares appearances, creates a fresh match ID and `SportsScoreJournal`, marks the match running, calls `BeginGame()`, configures explicitly assigned weather and enters the existing Play screen.
- `FixedUpdate()` calls simulation only while `Live` and the Play screen is active. `commands[slot]` and `actions[slot]` come from existing source ownership, device-neutral gates and action edge detection. `ReadDrive`, `ActionHeld`, `Ready`, `ValidateSources`, `Gate`, `Pause`, `Resume` remain authoritative.
- `EndMatch()` closes the score journal **before** `StopGame()`, records participants, stops sound and opens results. All final score/outcome receipts must therefore be confirmed before calling `EndMatch()`; cleanup must not attempt to create awards.
- `SetupScreen()` calls `StopGame()`, restores match colors, clears replacement sources and returns to setup. `OnDisable()` stops audio but does not call `StopGame()`. New mode-owned components must also make `OnDisable`/`OnDestroy` cleanup idempotent, including joints, ignored-collision pairs, pooled actors and callbacks.
- Setup is saved per derived type through `PreferenceKey`; option migrations use `OptionVersion`/`MigrateOption`. New equipment/species/co-op/seed choices can use a separate Dragon-specific versioned settings record rather than replacing the base private `Saved` format.

Use `SportsParticipantRegistry`, `SportsParticipantBinding`, `setup.players[slot].participantId` and the existing roster. `SportsParticipantRegistry.GetAppearance`, `TrySetAppearance`, `Rename`, `UseInSeat`, `Record` already preserve stable identities and results. Do not create a dragon-specific player/profile database.

`Assets/TruckSports/Scripts/SportsTruckAppearanceHost.cs` exposes `Prepare(string profileId, Color color)`, `RestoreOriginal()`, `ApplyEffectiveColor`, `CreateDashboard`, `ExteriorRenderers`, `AppearanceRoot`, `protectedRoots`, `modeOwnedSlots` and compatibility reporting. New saddle/cargo/carrier attachments belong under protected mode equipment roots, outside replaceable composed truck visuals. Do not write temporary equipment into saved appearance data.

`Assets/TruckSports/Scripts/SportsScoreEvent.cs` provides immutable receipts, not a rules engine. `SportsScoreJournal.TryConfirm` deduplicates by **event ID across the whole match**; include participant/object/round identity in IDs. `TryConfirmOutcome` records non-score measurements with `Kind=Outcome`, zero `Delta/Total` and nonnegative `OutcomeValue`. The mode owns its totals and winners before invoking protected `ConfirmScore` / `ConfirmOutcome` on the session. No award may come from HUD text, an animation starting, a timer pretending cargo arrived, or a VFX event.
