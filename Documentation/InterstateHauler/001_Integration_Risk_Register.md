# Interstate Hauler - Prompt 001 Integration Risk Register

Audit date: 2026-08-11  
Scope: project/vendor audit only. No implementation changes were made.

| ID | Severity | Area | Risk | Evidence | Impact | Recommended Prompt 002 action |
| --- | --- | --- | --- | --- | --- | --- |
| R001 | Critical | Render pipeline | URP packages and assets are installed, but no active render pipeline asset is assigned. | `GraphicsSettings.asset` and all `QualitySettings.asset` levels use `{fileID: 0}` for custom render pipeline. | Weather Maker, Weatherade, EasyRoads, VFX, and UI materials may render incorrectly or use the wrong code path. | Decide and assign the Standalone render pipeline asset, likely `Assets/Settings/PC_RPAsset.asset`, then validate vendor materials. |
| R002 | Critical | Build configuration | Build settings scene list is empty. | `ProjectSettings/EditorBuildSettings.asset` has `m_Scenes: []`. | Cannot make a meaningful build or use vendor streaming examples that depend on scenes in build settings. | Create or choose a project-owned bootstrap scene and add it intentionally. |
| R003 | High | Project health | Default volume profile has missing script references. | Exact `m_Script: {fileID: 0}` occurs five times in `Assets/Settings/DefaultVolumeProfile.asset`. | Active volumes can produce inspector/runtime noise or silently drop intended post-processing behavior. | Replace or clean the profile after render pipeline choice. |
| R004 | High | Git hygiene | Working tree was not clean at audit start. | Initial status included `?? Documents/`. | Prompt 001 should not auto-commit because unrelated untracked work may be mixed in. | Do not commit automatically. User should decide what to do with `Documents/`. |
| R005 | High | Git LFS | LFS policy is too narrow and includes stale generated Library patterns. | `.gitattributes` tracks three assets plus `Library/*` generated paths. | Future binary imports can exceed GitHub limits or pollute LFS policy with ignored files. | Clean `.gitattributes`; add broad Unity binary LFS patterns before more imports. |
| R006 | High | Weather integration | Weather Maker URP enablement is incomplete. | URP package is present, but no active RP asset and no obvious `UNITY_URP` define. | Weather Maker render features may be missing or inactive. | Run vendor URP setup only after project render-pipeline decision; record settings changes. |
| R007 | High | Weatherade integration | Weatherade URP paths are inactive. | `USING_URP` define is absent; URP support packages exist but referenced support classes were not in active source. | Rain/snow accumulation may not render or compile if the define is added without importing support. | Import/enable the matching Weatherade URP package only as part of a controlled render-pipeline task. |
| R008 | High | Road/terrain | EasyRoads runtime road edits can mutate terrain state. | Vendor runtime example warns to restore road network/terrain on destroy. | Play-mode testing can accidentally leave terrain changes. | Wrap EasyRoads runtime calls with restore/backup policy; prefer offline/exported graph data. |
| R009 | High | Road graph | No authoritative truck road graph exists. | Compass displays routes, UTS follows demo paths, EasyRoads owns road geometry. | GPS, ETA, jobs, AI traffic, depots, and saves will disagree. | Build `LwsRoadGraph` from EasyRoads samples and use it as the only routing source. |
| R010 | High | Vehicle input | NWH legacy input axes are not configured. | `InputManager.asset` lacks expected NWH axes such as `Steering`, `Throttle`, `Brakes`, `Clutch`, and `Handbrake`. | Player controls may fail if legacy provider is active. | Prefer new Input System through a project-owned NWH input provider; disable duplicate providers in scenes. |
| R011 | High | Truck transmission | Built-in NWH H-shifter supports only R, neutral, and 1-8. | `VehicleInputActions.inputactions` has `ShiftIntoR1`, neutral, and gears 1-8. | Cannot represent intended 18-speed trucking range/splitter accurately. | Create LWS range/splitter transmission adapter using NWH external/manual hooks. |
| R012 | Medium | Wheel hardware | Steering wheel / force feedback support is not active. | `SteeringWheelInput.unitypackage` exists only as an optional package; no active Logitech/FFB source found. | Hardware wheel support may be delayed or require vendor-package import. | Define wheel support as a later adapter; do not depend on active FFB in Prompt 002. |
| R013 | High | Player/NPC physics | UTS traffic uses WheelCollider and its own trailer joint system. | `CarMove` and `AddTrailer` are independent of NWH. | Mixing UTS with player truck/trailer can cause duplicate physics authorities. | Use UTS only for NPC traffic concepts/assets; NWH remains player/trailer authority. |
| R014 | Medium | Traffic tags | UTS AI depends on global tags. | UTS stops for tags including `Car`, `Bcycle`, `PeopleSemaphore`, `Player`, and `People`. | Tag collisions can produce false stops or missed interactions. | Create LWS traffic tagging/layer policy before importing UTS behavior into project scenes. |
| R015 | High | Terrain generation | Vista and EasyRoads both affect terrain-adjacent data. | Vista generates height/biome/population outputs; EasyRoads builds roads and can snap/mutate terrain. | Roads, vegetation, and biome masks can desynchronize. | Define generation order: Vista, EasyRoads, Spline/vegetation, navigation/traffic export. |
| R016 | Medium | Vegetation | Planned Vegetation Spawner FREE is not installed. | Targeted search did not find it; Vista and EasyRoads have related but different vegetation hooks. | Procedural roadside/biome population authority is ambiguous. | Decide whether Vista owns vegetation for now or install/adopt the planned vegetation tool later. |
| R017 | Medium | Spline Spawner | Package version metadata disagrees. | `package.json` says 1.2.0; `.meta` files report 1.2.1. | Upgrade state may be unclear when debugging package behavior. | Do not upgrade during Prompt 002; record exact files and validate only used API. |
| R018 | Medium | River Modeler | Package manifest and meta versions disagree. | `package.json` says 1.0.5; `.meta` files report 1.0.4. | Upgrade state may be unclear for water authoring. | Treat as authoring-only until water integration is needed. |
| R019 | Medium | Path Painter | Version log and meta version disagree. | Version log begins at 2.1.13; metadata sweep showed 2.1.12. | Possible partial import or stale metadata. | Treat as editor-only and avoid runtime dependencies. |
| R020 | Medium | Scene streaming | Pixel Crushers Scene Streamer needs build-settings discipline. | Its example requires scenes in build settings; project build settings are empty. | Streaming tests will fail unless scenes are added deliberately. | Use an LWS streaming facade if Scene Streamer is adopted; do not copy demo setup wholesale. |
| R021 | High | Save ownership | Multiple vendors can save partial state. | Pixel Crushers Save System, Compass save/load, and NWH state all exist separately. | Save files can become incomplete or inconsistent. | Create one `LwsSaveService`; vendor payloads become child adapters. |
| R022 | Medium | Compass routing | Compass is a route renderer, not the truck route solver. | `CompassPro.SetRoute` consumes world points; NavMesh helper uses `NavMesh.CalculatePath`. | GPS may route off-road or ignore truck restrictions if misused. | Feed Compass from `LwsRoadGraph`, not from generic NavMesh paths. |
| R023 | Medium | Color management | Project is in Gamma color space. | `m_ActiveColorSpace: 0`. | Weather, lighting, and vehicle materials may look wrong compared with vendor assumptions. | Decide whether to switch to Linear during render-pipeline setup and perform visual QA. |
| R024 | Medium | Version-control metadata | Unity settings disagree on visible/hidden meta files. | `EditorSettings` says hidden meta files; `VersionControlSettings` says visible meta files. | Team workflows can become confusing around meta visibility. | Normalize Unity version-control settings in a controlled project-settings change. |
| R025 | Low | Missing planned assets | Shift UI and Weather Sound FX Loops are not installed. | Targeted search did not find standalone installs. | UI/audio plans may assume unavailable assets. | Use installed Heat UI and existing audio temporarily, or install planned assets in a separate vendor-import task. |
| R026 | Medium | API/security | Pixel Crushers OpenAI addon can store API keys in Unity assets. | Runtime settings warn against distributing plain-text keys; runtime source is gated by `USE_OPENAI`. | Shipping secrets in builds is a security risk. | Keep `USE_OPENAI` disabled unless a secure server/token flow is designed. |
| R027 | Medium | Static singletons | Several vendor systems use singleton/static registries. | NWH `InputProvider`, Compass `CompassPro.instance`, Weather Maker singleton/provider, Weatherade coverage instance. | Multi-scene bootstrap can create duplicate or stale managers. | Create a bootstrap ownership map and validate one active manager per domain. |
| R028 | Low | Build target | Static files did not authoritatively expose active build target. | Generated Library profiles suggest Windows Standalone, but no Unity query was run. | Platform-specific symbols/settings may be assumed incorrectly. | Confirm active build target in Unity before platform-specific Prompt 002 edits. |

## Highest Priority Sequence

1. Resolve render pipeline activation and missing volume profile scripts.
2. Create or select a project-owned bootstrap scene and build-settings entry.
3. Establish LWS service boundaries for vehicle input, road graph, weather, save, and streaming.
4. Keep vendor packages untouched until each integration is wrapped and validated.
