# Prompt 020 - Depot and Job Board

Prompt 020 adds the first authored gameplay-content layer: depot presence, an authored job catalog, a job board service/UI, and one active-job semantic authority.

## Architecture

- `ILwsDepotService` / `LwsDepotService`: resolves depot definitions, tracks canonical player tractor depot presence, and requests `FREE_DRIVE -> AT_DEPOT` only when appropriate.
- `LwsDepotRuntime`: scene-side trigger/interaction component. It resolves colliders to the canonical `LwsPlayerTruck`, guards multi-collider entry, and ignores trailer-only entry.
- `ILwsJobCatalogService` / `LwsJobCatalogService`: runtime-safe authored catalog loader. Current validation catalog is loaded from `Resources/InterstateHauler/Gameplay/IH_JobCatalog_Validation`.
- `ILwsJobOfferProvider` / `LwsAuthoredJobOfferProvider`: production authored job provider. It filters enabled `LwsJobDefinition` assets by origin depot and does not randomize jobs.
- `ILwsJobBoardService` / `LwsJobBoardService`: opens/closes the board, queries offers, tracks selection, validates acceptance, creates an active job, requests autosave, and transitions to `TRAILER_PICKUP`.
- `LwsJobBoardPresenter`: standard Unity UI fallback for the job board. Heat was audited but not used directly because no existing Heat job-board window/presenter was configured for this project yet.
- `LwsJobBoardTerminal`: generated validation-world interaction prompt and stationary/range gate.

## Current Validation Depot

- Stable ID: `depot.validation.interstate-corridor`
- Display: `Interstate Validation Depot`
- World: `world.interstate-corridor-validation`
- Runtime location: generated by `LwsInterstateCorridorRuntimeBuilder` on the existing service/trailer pad.
- Art: simple project-owned validation terminal/sign, marked validation art and not final depot art.

## Interaction

The driver remains in the truck. When the canonical tractor is inside the validation depot, near the terminal, and at or below 1 MPH, the prompt shows `JOB BOARD AVAILABLE` and `[ENTER] OPEN JOB BOARD`.

Opening the board requests `AT_DEPOT -> JOB_SELECTION`. Closing without acceptance returns to `AT_DEPOT`. Accepting a job creates an active job and transitions to `TRAILER_PICKUP`.

## State Policy

Depot presence is not gameplay state. The depot service only transitions from `FREE_DRIVE` to `AT_DEPOT` and from `AT_DEPOT` back to `FREE_DRIVE` on exit. Entering a depot during future haul/delivery states updates presence only.

## Input Policy

`JOB_SELECTION` has `AllowsDrivingInput = false`. The existing NWH input provider, truck control controller, and 18-speed transmission controller respect macro driving permission without replacing input ownership, wheel support, or Prompt 006 transmission authority.

## Autosave

Job acceptance calls the existing Prompt 017 save facade autosave seam with reason `job.accepted`. It does not call Pixel Crushers directly and does not create a second autosave system.
