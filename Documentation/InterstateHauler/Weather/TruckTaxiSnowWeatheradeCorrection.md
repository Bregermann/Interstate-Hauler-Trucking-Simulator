# Truck Taxi snow correction

Taxi lane cells in `TruckTaxiSnowRegion` now contain gameplay depth only. `TruckTaxiSnowSurface` creates no raised snow surface and no snow collider. NWH wheel grip and rolling resistance respond to contact-local depth; at zero depth the Taxi modifier is neutral. `TruckTaxiSnow.ClearSnow()` is an explicit debug/test reset, while normal clear weather melts existing depth at the configured rate.

## Installed APIs used

- `Assets/NOT_Lonely/Weatherade SRS/Scripts/SnowCoverage.cs`: public `coverageAmount` and inherited `UpdateCoverageMaterials()` drive continuous accumulation. The existing `LwsWeatheradeAdapter.ApplyRoadCondition()` binds snow-compatible road materials and owns the coverage component lifecycle.
- `Assets/NOT_Lonely/Weatherade SRS/Scripts/SRS_TraceMaskGenerator.cs`: component `Init()` and its Inspector-serialized `traceSurfLayermask`, `traceObjsLayermask`, and `decaySpeed` produce the vendor `_SRS_TraceTex` mask. Taxi configures these existing fields through its reflection adapter because Weatherade lives in Assembly-CSharp, which `LWS.TruckTaxi.Runtime` cannot reference directly.
- `Assets/NOT_Lonely/Weatherade SRS/Shaders/Extra/DepthOccluder.shader`: vendor `_Render=0` material feeds hidden, collider-free road-depth proxies on runtime layer 30 and plow/wheel trace volumes on runtime layer 29. The existing snow shader's `_TracesOverride`, `_Traces`, and `_TRACES_ON` properties enable the mask on Weatherade road materials. No vendor source, scene layer, or road collider is changed.
- `Assets/NWH/Common/Scripts/Vehicle/WheelUAPI.cs`: public `IsGrounded`, `HitPoint`, `Width`, grip, and rolling resistance properties provide actual per-wheel contacts and mechanical response.

The vendor trace mask fades at a configured decay rate; new snowfall therefore covers tire tracks and plowed channels. Hidden road proxies exist solely because this project has no dedicated road/tracer layers in `ProjectSettings/TagManager.asset`. Layers 29 and 30 are unnamed and unused in the Taxi scene and prefabs; layer 31 was rejected because an inactive vendor `surface` scene object already uses it. The proxies reuse existing road meshes for Weatherade's depth camera, not visible snow or collision geometry. The vendor depth-occluder shader outputs alpha zero with `_Render=0` but also writes depth, so Taxi excludes these two layers from enabled gameplay cameras at runtime and restores their masks on disable.

The Taxi `Ground` object is the only authored non-road `TruckTaxiSurface` in the demo scene and uses the `Park green` URP material, not a Weatherade shader. Taxi now binds this Ground/shoulder plane to a temporary Weatherade snow material through `LwsWeatheradeMaterialFactory`, restoring the original material when snow coverage ends. The scene has no Unity Terrain component; future terrain would require a Weatherade terrain material/adapter setup, not just the current road proxies.

## Parent integration and validation

Run `Truck Taxi/Migrate Snow Rates` for an existing settings asset. It upgrades only the three legacy rates (`.0005/.002/.005` m/s), plus absent melt/compression fields. Defaults target 0.6 m in 90s light, 35s heavy, and 25s blizzard; clear-weather melt defaults to 0.01 m/s and the plow residual remains 0.04 m. Custom non-legacy rates remain unchanged. `Truck Taxi/Configure Snow` also invokes migration and retains the depth-occluder shader for a player build, but saves the scene and is parent-owned to run.

Parent integration ran `TruckTaxiSnowTests` (7/7) and a focused Play Mode runtime/render check. Blizzard reached at least .58 m within 27 seconds. The gameplay render showed nearby continuous snow and paired wheel tracks; GPU readback confirmed nonzero trace-mask and indentation pixels. No raised Taxi snow mesh/collider remained. Plow channel appearance and long-term refill aesthetics remain designer review items.

The scene retains the installed Snow_01/SnowDetail/SparkleMask textures and vendor shaders as player-build dependencies. Runtime-generated snow materials receive the vendor `UpdateCoverageMaterial` call because they are created after its initial material collection. Editor setup resolves `SRS_DepthRenderer` within the Taxi weather render pipeline and serializes its index (currently 1). The coverage camera and both vendor trace cameras use that renderer. Coverage excludes the hidden trace layers so trace helpers do not create a bare square around the player. An actual stop/start Play Mode check verified this saved configuration rather than relying on a live-only fix.

For the checkpoint, `TruckTaxiEditorSnowSetup.ConfigureScene(TruckTaxiBootstrap host)` is the in-memory scene setup entrypoint; `ConfigureDemoScene()` is the `Truck Taxi/Configure Snow` menu command that opens and saves the demo scene. `MigrateSnowSettingsAsset()` is the independent `Truck Taxi/Migrate Snow Rates` menu command. In Play Mode inspect `host.GetComponent<TruckTaxiSnowSurface>().Diagnostic` and `TraceMaskReady`: the latter checks that the installed generator is active and its private `traceTex` render texture exists. `RoadDepthSourceCount` should be positive after Weatherade binds compatible road meshes. These are readiness diagnostics, not proof that the mask looks correct on screen.

`TruckTaxiExpansionProbe` and `TruckTaxiSnowRuntimeProbe` now check Weatherade mask readiness and absence of raised Taxi snow geometry. `VisibleCellCount` still reports hidden depth cells for API compatibility; `TruckTaxiSnowSurface.RenderedCells` is always zero and `DepthCollider` is null. The installed `Resources/DepthOccluder.mat` references the same vendor shader GUID as `DepthOccluder.shader`, and `Configure Snow` additionally records that shader in the Taxi build-retention array.
