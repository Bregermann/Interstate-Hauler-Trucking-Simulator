# Truck Taxi snow correction

Taxi lane cells in `TruckTaxiSnowRegion` contain gameplay depth only. `TruckTaxiSnowSurface` feeds actual wheel-contact stamps into Weatherade's snow indentation mask; it creates no visible snow mesh or snow collider. NWH wheel grip and rolling resistance respond to contact-local depth; at zero depth the Taxi modifier is neutral. `TruckTaxiSnow.ClearSnow()` is an explicit debug/test reset, while normal clear weather melts existing depth at the configured rate.

## Installed APIs used

- `Assets/NOT_Lonely/Weatherade SRS/Scripts/SnowCoverage.cs`: public `coverageAmount` and inherited `UpdateCoverageMaterials()` drive continuous accumulation. The existing `LwsWeatheradeAdapter.ApplyRoadCondition()` binds snow-compatible road materials and owns the coverage component lifecycle.
- `Assets/NOT_Lonely/Weatherade SRS/Scripts/SRS_TraceMaskGenerator.cs`: component `Init()` and its Inspector-serialized `traceSurfLayermask`, `traceObjsLayermask`, and `decaySpeed` produce the vendor `_SRS_TraceTex` mask. Taxi configures these existing fields through its reflection adapter because Weatherade lives in Assembly-CSharp, which `LWS.TruckTaxi.Runtime` cannot reference directly.
- `Assets/NOT_Lonely/Weatherade SRS/Shaders/Extra/DepthOccluder.shader`: vendor `_Render=0` material feeds hidden, collider-free road-depth proxies on runtime layer 30 and plow/wheel trace volumes on runtime layer 29. The existing snow shader's `_TracesOverride`, `_Traces`, and `_TRACES_ON` properties enable the mask on Weatherade road materials. No vendor source, scene layer, or road collider is changed.
- `Assets/NWH/Common/Scripts/Vehicle/WheelUAPI.cs`: public `IsGrounded`, `HitPoint`, `Width`, grip, and rolling resistance properties provide actual per-wheel contacts and mechanical response.

The vendor trace mask fades at a configured decay rate; new snowfall can therefore cover its tire tracks and plowed channels. Hidden road proxies exist solely because this project has no dedicated road/tracer layers in `ProjectSettings/TagManager.asset`. Layers 29 and 30 are unnamed and unused in the Taxi scene and prefabs; layer 31 was rejected because an inactive vendor `surface` scene object already uses it. The proxies reuse existing road meshes for Weatherade's depth camera, not visible snow or collision geometry. The vendor depth-occluder shader outputs alpha zero with `_Render=0` but also writes depth, so Taxi excludes these two layers from enabled gameplay cameras at runtime and restores their masks on disable.

## Visible wheel grooves

`TruckTaxiSnowTraction` accumulates real NWH wheel-contact travel before stamping, so low-speed motion no longer loses marks between frames. Stamps require at least 0.04 m snow depth and 0.06 visual coverage; bare/dry road creates none. Road tracks use contact-local lane depth, preserving plow/compression semantics. Snow-covered ground/shoulders use background accumulation only when the actual NWH contact collider belongs to a non-road `TruckTaxiSurface`; the collider lookup is cached per wheel. Other unmarked surfaces receive no background-depth fallback. Deeper snow increases the vendor trace volume. The trace mask remains Weatherade's `_SRS_TraceTex`, with 0.003 time-based mask decay.

All grounded NWH wheels stamp their actual paths. The vendor mask scrolls with its existing 180 m coverage area and uses fixed 1024x1024 textures (512x512 for surface depth), independent of distance driven. A reusable invisible box per wheel supplies contact sweeps; no decal objects or visible mesh chunks accumulate. Stationary stamps stop after 0.75 s. Teleports over 5 m break continuity. The vendor history decays from its 0.5 peak at 0.003 per second, roughly 167 seconds while the track remains in the local coverage area. Moving beyond that area retires distant history. Blur kernel 2, border intensity 0.7, normal spread 1.3, and trace normal scale 1.35 make the grooves and displaced edges readable. These settings are in `TruckTaxiSnowSurface.EnsureTraceGenerator` and `ConfigureTrackAppearance`; depth gating is in `TrackStrength`.

The player-build visual failure was shader stripping. Runtime-created materials enabled `_COVERAGE_ON` and `_TRACES_ON`, but no build-retained material used those combinations. The mask had indentation pixels while the player rendered bare asphalt. Two project-owned Resources materials now retain the exact feature combinations: `Assets/LWS/TruckTaxi/Resources/TruckTaxi/Snow/SnowCoverage.mat` and `SnowCoverageTracks.mat`. `Truck Taxi/Retain Snow Shader Variants` creates/updates them through Unity's asset API and `Configure Snow` invokes the same helper. Unity documents this requirement under [shader conditionals](https://docs.unity3d.com/2022.3/Documentation/Manual/shader-conditionals.html). The corrected Windows capture showed the snow blanket and indented tracks. The temporary supplementary relief ribbons were removed because the working vendor shader provides the requested effect.

Taxi snow temporarily pauses the shared `LwsWeatheradeAdapter`'s road-condition visual subscription while it owns accumulated snow coverage, then reattaches it on clear. This prevents the road-condition service from swapping SnowCoverage for RainCoverage mid-drive and wiping the vendor trace texture. Road-condition physics and Weather Maker weather presentation are unchanged.

The Taxi `Ground` object is the only authored non-road `TruckTaxiSurface` in the demo scene and uses the `Park green` URP material, not a Weatherade shader. Taxi now binds this Ground/shoulder plane to a temporary Weatherade snow material through `LwsWeatheradeMaterialFactory`, restoring the original material when snow coverage ends. The scene has no Unity Terrain component; future terrain would require a Weatherade terrain material/adapter setup, not just the current road proxies.

## Parent integration and validation

Run `Truck Taxi/Migrate Snow Rates` for an existing settings asset. It upgrades only the three legacy rates (`.0005/.002/.005` m/s), plus absent melt/compression fields. Defaults target 0.6 m in 90s light, 35s heavy, and 25s blizzard; clear-weather melt defaults to 0.01 m/s and the plow residual remains 0.04 m. Custom non-legacy rates remain unchanged. `Truck Taxi/Configure Snow` also invokes migration and retains the depth-occluder shader for a player build, but saves the scene and is parent-owned to run.

The final focused `TruckTaxiSnowTests` run passed 9/9, including retained player shader keywords and local-depth gating (`Logs/TruckTaxiSnowTracks.VendorFinal.EditMode.xml`). The Windows development build succeeded with zero build errors (`Logs/SnowTracks-VendorFinalBuildEditor.log`). The opt-in player fixture (`-truck-taxi-snow-track-smoke`) drove straight and curved paths, stopped for eight seconds, changed to night, and cleared snow, reporting zero failures in `Logs/TruckTaxi-SnowTracks-VendorFinalPlayer.log`. GPU readback after stopping found 15,916 active trace pixels and 15,309 indented pixels. Normal-camera and top-down images in `Builds/TruckTaxiDemo/Validation/SnowTracks_*.png` were visually inspected: paired carved tracks, curved continuation onto snowy ground, persistence, low-light visibility, and removal on clear were visible. The nighttime capture is aimed at the recorded path. No new snow collider or full snow-surface mesh is added. A foreground player performance comparison remains required before claiming a frame-time win or neutral cost; the history allocation is fixed and the redundant relief-mesh work has been removed.

The scene retains the installed Snow_01/SnowDetail/SparkleMask textures and vendor shaders as player-build dependencies. Runtime-generated snow materials receive the vendor `UpdateCoverageMaterial` call because they are created after its initial material collection. Editor setup resolves `SRS_DepthRenderer` within the Taxi weather render pipeline and serializes its index (currently 1). The coverage camera and both vendor trace cameras use that renderer. Coverage excludes the hidden trace layers so trace helpers do not create a bare square around the player. An actual stop/start Play Mode check verified this saved configuration rather than relying on a live-only fix.

For the checkpoint, `TruckTaxiEditorSnowSetup.ConfigureScene(TruckTaxiBootstrap host)` is the in-memory scene setup entrypoint; `ConfigureDemoScene()` is the `Truck Taxi/Configure Snow` menu command that opens and saves the demo scene. `MigrateSnowSettingsAsset()` is the independent `Truck Taxi/Migrate Snow Rates` menu command. In Play Mode inspect `host.GetComponent<TruckTaxiSnowSurface>().Diagnostic` and `TraceMaskReady`: the latter checks that the installed generator is active and its private `traceTex` render texture exists. `RoadDepthSourceCount` should be positive after Weatherade binds compatible road meshes. These are readiness diagnostics, not proof that the mask looks correct on screen.

`TruckTaxiExpansionProbe` and `TruckTaxiSnowRuntimeProbe` now check Weatherade mask readiness and absence of raised Taxi snow geometry. `VisibleCellCount` still reports hidden depth cells for API compatibility; `TruckTaxiSnowSurface.RenderedCells` is always zero and `DepthCollider` is null. The installed `Resources/DepthOccluder.mat` references the same vendor shader GUID as `DepthOccluder.shader`, and `Configure Snow` additionally records that shader in the Taxi build-retention array.
