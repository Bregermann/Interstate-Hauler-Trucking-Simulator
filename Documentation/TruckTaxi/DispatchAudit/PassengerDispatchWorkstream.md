## Implementation

- Selection uses stable-ID exposure, not asset references or a fixed permutation.
  Minimum exposure is prioritized, followed by a randomized least-recent window.
  Context/rarity weights affect ordering with bounded influence, not lifetime starvation.
- Offered, accepted, completed, last offer index, last game minutes, and broad archetype
  are independently recorded. Only a presented, route-valid offer advances exposure.
  Declines/expiry still count as exposure, but do not advance completion cooldowns.
- Dynamic district/work-area/continuity/range/availability checks are rerun each offer.
  Missing stable IDs, duplicate IDs, nonfinite weights, and nonpositive weights are
  excluded. Excluded IDs retain their previous exposure for future eligibility.
- Broad archetype runs stop at two when alternatives exist. Recent category saturation
  is also downweighted. Racing caps are 3 in 20 ordinary offers or 6 in 20 event offers,
  plus suppression after two in the last four. Constraints relax only if no eligible
  non-racing alternative remains. Such constrained rosters cannot guarantee both
  equal exposure and a fixed category ceiling.
- Root cause found: old `PrefersSpeedway` classified anyone with a shared `TakeALap`
  request as racing-themed. Large parts of the cast share that request. Racing now
  uses authored category/tags/archetype and existing `racing-` authoring IDs only.
  The authored `glam-` group is similarly a broad category, never a gender inference.
- Racing weight: no ordinary-world boost, at most 1.15 near Speedway, at most 1.5
  during an explicitly signaled race event. Existing serialized weight 3 is bounded.
- Manual decline records decline and starts incremental replacement generation
  immediately with zero dispatch delay. Alternative passenger/pickup/destination
  IDs are preferred; path failures fall back to other bounded candidates. Expiry,
  recovery, and work-area invalidation keep ordinary scheduling.
- Intercity spacing is enforced at the session boundary: two COMPLETED locals after
  an intercity completion, guarantee after three completed locals. Legacy serialized
  spacing 3/threshold 5 cannot silently reinstate the previous policy. Only actual
  completed destination regions reset the drought. Declines/cancellations do not.
  When no cross-region metadata exists, local work continues and the drought remains.
  When cross-region candidates exist but every tried route fails, the guarantee remains.
- Explicit gender is resolved from the new enum first, then exact existing authored
  casting tokens `Male`, `Man`, `Female`, `Woman`. No name, model, voice, dialogue,
  presentation booleans, or ambiguous casting text supplies missing gender.
- The central metadata predicate requires explicitly female, explicitly adult, age
  at least 21, and an explicit opt-in. The probability is exactly .33 after eligibility,
  without extra five-star, satisfaction, time, casting-species, or presentation gates.
  Legacy probability/satisfaction fields are retained for serialization compatibility.
  Existing accept/decline state transitions and penalty-free decline remain in place.

## Parent Integration APIs

- `TruckTaxiSession.CapturePassengerSelectionState()` returns a detached, serializable
  `TruckTaxiPassengerSelectionState` (version 1, offerIndex, per-ID records, recent archetypes).
- `RestorePassengerSelectionState(snapshot)` validates atomically and returns bool.
  Call in Inactive or Available state with no offer generation underway. It also restores
  accepted-ID repeat recognition. It does not restore continuity, wallet, or storage.
- `IntercityPolicy.CaptureState()` / `RestoreState(TruckTaxiIntercityState)` preserve
  completed-local drought and cooldown; legacy larger cooldowns are bounded to current spacing.
- `CapturePassengerEligibility()` returns detached current pickup-metadata audit rows;
  route status is explicitly pending. `LastOfferRejectedPickupRoutes`,
  `LastOfferRejectedDestinationRoutes`, `LastOfferCandidateCount`, and diagnostics expose
  actual attempted route gates. `OffersGenerated`, `OffersDeclined`, `OffersExpired`
  support telemetry. Full session persistence remains parent-owned.
- Parent world-event coordination must set `RaceEventActive` from actual race-event state.
- `PassengerProfile.customInteractionProfile` and `customItemInteractions` are optional
  references only, with the latter defaulting to an empty array.
- `PassengerRequestDefinition.requiredItemStableId` / `requiredCustomEventId` plus an
  explicit objective ID and finite positive target are required for CustomItemAction.
  The active runner calls `Capabilities.RegisterCustomItemAction(eventId,itemId,true)`
  and unregisters with `false`. A capability bit alone is insufficient. Unknown,
  disabled, unregistered, mismatched, or malformed pairs are excluded. Session assignment
  additionally requires a known ownable item and a matching explicitly attached
  passenger interaction. No content meanings are encoded in event IDs or item matching.
  Parent event/reward execution stays in its new partial; it should also check current
  capability support before progressing a goal if a runner is disabled mid-ride.
