## Physical objectives and authority

`HoardHeistMatch` extends the shared `DragonKingdomGroundMatch`. The shared owner retains NWH driving, original participant/profile customization, input, road navigation, weather/time, cameras, Compass, Heat UI and match lifecycle. This mode supplies objective preparation/tick/goal/prompts, quiet command filtering, stationary NWH handbrake holds and recovery cleanup.

The installed Malbers `MPickUp/Pickable` was audited: picking disables gravity/collisions, optionally makes a body kinematic, and parents it into a holder. That is unsuitable for physical weighted/spillable cargo. The mode instead reuses the existing `JengaCrane` already used by Archaeology: actual approach, lower, joint grip, lift, traverse, lower and release. A small mounted visual adapter replaces that crane's world-origin warehouse bridge presentation; it does not replace its load motor. Spreader parking moves through physics; it is not teleported during a heist.

Original treasure remains dynamic. A settled real rack load receives a breakable FixedJoint to the actual truck. Item count and mass limit each load; reserved lifts also consume capacity. Actual mass/inertia remain in PhysX/NWH. Bumps can break the restraint and leave the same item recoverable by competitors. Clearance casts refuse obstructed lifts; changed rack positions or a failed lift release the original object rather than inventing success. The recovery hook drops cargo before the shared truck recovery moves its crew.

`HoardHeistRules` captures each original Rigidbody identity. A value award requires the correct owner/state/body, a dynamic secured item, all eight physical box corners inside the actual extraction collider, a stopped truck and settled cargo. Each original item can score once. Received items physically unload through the same hoist where clear, and do not become collectible again. Lost/unbanked items do not score. Three/five/eight minute options close the heist; time itself awards nothing. Results derive only from received value and retain genuine ties.

The four AI crews follow the same roads, hoist and cargo proof. They choose available finite items, brake/handbrake for real loading, respect capacity, feather throttle near the guardian, wait at authored cover when suspicion rises, withdraw when awakened, physically bank cargo and return when conditions permit. There is no scripted AI winner or injected treasure.

## Guardian and noise

The guardian is the shared real Inferno/Malbers actor, with genuine Sleep/Wake/Roar/Breath/Claw actions. It uses the same public actual-LOS query and remembered-target API as the actor. Engine/horn noise comes from the shared sampler; this mode adds load/noise semantics and actual collision, dropped cargo and pottery-collapse events. Obstruction attenuates hearing, quiet decays suspicion, and a real threshold crossing latches until the animated wake sequence can run. The dragon is not fed hidden truck poses.

Sleeping, restless, suspicious and investigating states include the curled vigilance action. Wake completion permits roar/pursuit. A lost target sends the actor toward the actual last sensed position and then home; an undisturbed return resumes sleep. Real observed roar/attack contacts release the bounded falling cave rocks. Cover/wake/chase/hoist context uses existing `SportsBroadcastFraming` objectives and its truck readability limits, retaining Cinemachine authority. Existing driving/cockpit/spectator views remain shared.

The returning airborne guardian uses the actual shared `RequestLanding` near home and retains that pending request instead of canceling it with a new intent every frame. Land is intentionally a vendor base-state animation, excluded from Mode actions; the initial consumer's `TryAction(Land)`/`ActionFinished(Land)` wait was therefore impossible and has been removed. The current consumer captures the read-only `CompletedLandings` baseline before requesting the landing and waits for a larger actual completion count, actual native `IsGrounded`, no flying state and no `LandingPlaying` or other active action before sleeping. The motor owner increments that counter only after observed mapped weighted Land playback and its natural exit; Heist does not fabricate an action event or force a transition. A guardian already safely grounded does not demand a new landing. New sensed pursuit clears return bookkeeping. This correction has source-compilation evidence only; actual landing/home/sleep transitions remain a native visual acceptance item.

CoreCollapse `Collapser.ReceiveAllDamage`/`Support.OnCollapse` own pottery collapse. A thin adapter activates preauthored same-model shards and emits the actual crash noise. `CreateOwnedFragments(...)` is public for the other kingdom modes: it preserves every original material surface through the existing `SportsTruckFragmentRecipeAuthoring.ClipOwnedWorkingMesh` EzySlice adapter, groups surfaces into bounded cells and saves real derived meshes privately. Editor read-only vertex/index snapshots produce a readable working clone without modifying the vendor importer. This uses Unity's documented [MeshUtility read-only snapshot API](https://docs.unity3d.com/6000.0/ScriptReference/MeshUtility.AcquireReadOnlyMeshData.html). Existing narrowly justified sliver/tangent repairs stay in the shared adapter; no broad normal/UV replacement is introduced.

`OwnedUrpMaterial(source, modeFolder)` reuses shared kingdom material variants first, otherwise creates a project-owned variant in the caller's mode folder. Source textures/materials stay untouched. Coin impact/pot smash WAVs are actual owned Epic Sounds files; playback is bounded to one treasure source at a time and respects SFX volume. Audible mix quality has not been listened to in this workstream.
