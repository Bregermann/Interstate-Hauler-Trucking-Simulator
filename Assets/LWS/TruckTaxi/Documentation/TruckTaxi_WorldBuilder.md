# Truck Taxi World Builder

Open **Truck Taxi > World Builder** in the Unity Editor. Place an empty GameObject at the intended world position and name it `TT_<PREFIX>_<Name>`. Use **SCAN SELECTED ANCHORS** for the selected hierarchy or **SCAN ALL ANCHORS** for loaded scenes. The tool adds a `TruckTaxiWorldAnchor` with a UUID once, adds only missing components, and never moves an authored transform or resets an existing component. Save the scene after authoring. Duplicate stored UUIDs are reported and stop configuration; give a copied anchor a fresh component rather than editing its UUID.

Prefixes: `SCENIC`, `ILLICIT`, `PRIVATE`, `STORE`, `GAS`, `RESTROOM`, `PICKUP`, `DESTINATION`, `PEDAREA`, `CROSSWALK`, `TRAFFICLIGHT`, `SHORTCUT`, `PROPERTY`, `PARKING`, `BUILDING`. Parking and building are metadata-only content anchors. Store and gas map markers currently use the installed `FoodStop` and `Destination` icon types respectively; dedicated icons can be added to the shared icon registry later. The point's world position is its stopping/navigation position unless the designer configures an existing `TruckTaxiRideLocation` stop transform. Gas recovery initially uses the anchor itself and can be moved by assigning an authored recovery transform.

`PEDAREA` invokes `EditorTrafficSandboxSetup.ConfigurePedestrianArea` only when no area component exists. `CROSSWALK` and `TRAFFICLIGHT` invoke `ConfigureIntersection` only when no intersection exists. These require the scene's existing UTS pedestrian population and source walking path. The UTS helper instantiates the vendor semaphore/path and connects the population; the World Builder does not fake signal logic. Place pedestrian areas off active lanes. The helper may reject an overlapping area. A traffic-light or crosswalk anchor produces one complete intersection; do not stack separate prefixes at the same location.

For roads, name an empty `TT_ROAD_<Type>_<Name>` and create direct empty children `P00`, `P01`, and so on with no gaps. Supported types: `CityStreet`, `Avenue`, `Highway`, `Alley`, `ServiceRoad`, `DirtRoad`, `ParkingConnector`. Their world positions are EasyRoads spline markers; the tool does not move them. **BUILD SELECTED ROAD** creates a new road; **UPDATE SELECTED ROAD** updates only an already created road's markers; **BUILD NEW ROADS** skips existing ones. Road type defaults are applied only on creation. The tool uses EasyRoads public `ERRoadNetwork`/`ERRoadType`/`ERRoad` APIs through reflection because EasyRoads is in `Assembly-CSharp`. Terrain deformation and snap-to-terrain are disabled for new roads.

The road tool requires exactly one `LwsRoadGraphProvider` in the same scene and refuses an invalid source graph. It adds or replaces only its own `tt.world.road.<UUID>` edge, connecting endpoints within 5 m of existing nodes. Existing city edges and nodes are retained. Intermediate spline markers are graph samples, not junction nodes. Explicit EasyRoads intersection authoring and traffic-lane/path regeneration remain separate workflows. `VALIDATE ROAD GRAPH` checks the active scene graph and anchor IDs. EasyRoads' own object/terrain mutation has best-effort Undo recording; save/backup before major road edits and inspect the resulting mesh and road graph.

`TruckTaxiWorldBuilder.ConfigureExamples()` is a static parent integration entry point. In the open `TruckTaxi_DemoCity` scene only, it stages a small, fixed set of empty example anchors and one road under `Truck Taxi World Builder Examples`. It configures gameplay anchors, reports UTS setup failures, and leaves existing example transforms untouched. It does not itself build or save. The integration pass executed it, built and updated `TT_ROAD_ServiceRoad_East_Connector` through EasyRoads, and saved the scene. Repeating setup preserved all 16 UUIDs/transforms; building then updating preserved the 58-node/209-edge road graph rather than adding duplicate edges. `MergeRoad(graph, id, kind, points)` is the pure graph helper entry point.
